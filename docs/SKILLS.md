# Skills, plugins and connectors used on LUMIERE

Installed 2026-10-30. Project skills live in `.claude/skills/` (checked into git), so every Claude Code session opened on this
repo, including sessions started from the Claude app on the phone, loads them. `.claude/hooks/session-start.sh` reinstalls
Kiln and the comment-lint parser in each cloud session (pinned versions, skipped when already installed).

"Mobile" below means: you work only from an Android phone. Skills are instructions Claude reads, so they work in any Claude Code
session you open from the phone (claude.ai/code). The tools some skills drive run on the cloud machine; the last column says
whether they would also run inside Termux.

## Blender toolchain in the cloud session
- `blender` = Blender 5.2.3 LTS (`/opt`, checksum verified by `.claude/hooks/session-start.sh`). Headless only: `blender --background --python script.py -- args`.
- Cycles renders and bakes on the CPU (4 cores). EEVEE renders through Mesa's software OpenGL (slow: ~30 s of shader compile per session).
- No Blender MCP (a cloud session has no Blender window). The cc-blender skills' `mcp__blender__*` calls are replaced by headless scripts.
- `gltf-transform` 4.5.1 (on PATH after the hook) inspects and validates GLBs.
- v5.20 uses it for real: `tools/blender/seats.py` and `fixtures.py` model the hall seating and light fittings (the blender-modeling
  recipes: bevelled rounded parts, overlapping joins, smooth shading); `tools/bake/bake_room.py` bakes every room's light in Cycles
  (blender-web-3d `references/baked-lighting.md`, cc-blender blender-uv-texturing / blender-lighting).
- Textures: `tools/textures/gen.py` (procedural baseline) then `tools/textures/fetch_cc0.py` (Poly Haven / ambientCG CC0 scans; provenance in
  `tools/textures/SOURCES.md`).

## Left out, and why
- `threejs-r3f`, `threejs-react-three-fiber`: the app has no React.
- `threejs-xr`, `threejs-spatial-data`, `threejs-product-viewer`, `threejs-deployment`: no VR, maps, product viewer or web hosting here.
- `threejs-webgpu`: Android WebView in this app uses WebGL 2 (three.js r169); WebGPU is not reliable there.
- img2threejs `forge/tests`, CI scripts and its plugin harness (`npx @img2threejs/img2`): not needed to use the skill, and the
  harness downloads more code at run time.
- anthropics/skills `webapp-testing`: duplicates the Playwright plugin and `tools/dev/shoot.mjs`.
- gamedev-skills/awesome-gamedev-agent-skills three.js entries, Jeffallan/claude-skills `game-developer`, majiayu000 `3d-modeling`:
  overlap the sets above with less depth.

## Security review (done before install)
- Read each repository's scripts and searched every installed file for remote shell pipes, credential paths and tokens,
  `eval`/`exec` of downloaded text, destructive commands and instructions aimed at the agent. Nothing malicious found.
- img2threejs runs one subprocess (its own generator, with a timeout) and its installer only runs `git`; neither is used here.
- Nothing installed needs an account, key or payment.

## Using them (rule for every future task)
- Phone feedback about speed or flicker: `threejs-performance`, `threejs-debugging`, then `threejs-api-performance`.
- Shaders, materials, video picture: `threejs-shaders`, `threejs-materials`, `threejs-api-textures`.
- People and crowd motion: `threejs-animation`, `threejs-api-animation`; particles (popcorn, money): `threejs-particles`.
- Sound: `threejs-audio`. UI motion: `animation-forge`, `frontend-design`. Props: `kiln-author-asset` then `kiln-qa-asset`.
- New feature: `superpowers:brainstorming` first; bug: `superpowers:systematic-debugging`; before claiming done:
  `superpowers:verification-before-completion`.

## Updating or removing
- Update a skill: clone its repository at a newer commit, re-run the security review, copy the folder over, update this table.
- Remove: delete its folder in `.claude/skills/`. Remove the hook: delete `.claude/hooks/` and `.claude/settings.json`.
